# 原生状态与扩展状态的证据边界

本机锁定 hf-libero 0.1.3 的实测结果：Spatial/Object 各任务的状态文件都含 50 个精确不同的向量。文件后缀带 pruned 不代表本版本只有 20 个，计数以实际加载为准。

LIBERO 官方仓库维护者在 [Issue 34](https://github.com/Lifelong-Robot-Learning/LIBERO/issues/34) 说明，固定初始状态由不同随机种子多次初始化环境后保存得到；原项目采集过 50 个，并可选 20 个用于加速评估。因此通过真实 reset 和保存模拟器状态生成更多候选状态，在上游方法上有依据。

这不等于本项目已经验证了 100 个可用状态。扩展前需要记录生成器版本、seed 与原始完整 simulator state；确认 object placement 不只是 time 或机器人浮点噪声不同；排除与已有池近似重复的物体配置；检查 reset 合法、初始目标未完成、目标可见、三档背景合法；重新加载相同状态后验证 settling 和七条件配对一致。需要明确新状态与原 benchmark 固定池的分布关系。

当前没有通过换 seed 重跑相同 set_init_state 冒充新增样本，也没有生成虚假的状态或 success。原生 50 状态方案与扩展 100 状态方案应在正式采集前由用户根据研究协议和预算选择。筛选/Pilot 数据不会因此变成正式样本。
